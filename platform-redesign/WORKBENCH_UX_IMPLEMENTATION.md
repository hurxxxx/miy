# Workbench 데스크톱 UX 구현 기록

2026-10-12. [화면 검토와 개선안](WORKBENCH_UX_REVIEW.md)을 바탕으로, 첫 행동·현재 진행·필요한 결정·기존 결과를 쉽게 찾도록 구현했다. 사용자 요청에 따라 모바일 재설계는 제외하고 앱 확인은 새 탭 링크로 제공한다. 로컬 구현·검증 후 사용자의 별도 배포 요청으로 **독립 Workbench r25·r26을 설치했다.** 배포 산출물의 기준 커밋·변경 유무는 아래 릴리스 식별 기록을 따른다.

현재 사용 계약은 [Workbench 소유 문서](../docs/apps/codex-console/README.md)가 관리한다. 이 문서는 변경 이유와 검증 근거를 기록한다.

## 사용 경험의 변화

| 사용자가 해야 할 일 | 구현한 동작 |
| --- | --- |
| 처음 앱을 만들기 | 공통 메뉴의 ‘앱 만들기’와 Studio 빈 프로젝트 안내에서 시작한다. 빈 프로젝트 목록을 앱 카탈로그로 자동 전환하지 않는다. |
| 어디로 이동할지 알기 | 공통 사이드바 하나에 Studio·앱 관리·작업 기록을 두고 보조 기능은 도구에 모았다. 앱/프로젝트는 본문 목록에서 고른다. |
| 지금 해야 할 결정 찾기 | Studio의 ‘내 확인이 필요한 작업’을 진행 중인 작업과 구분했다. 질문·승인은 작업실 상단에서 한 요청씩 답한다. |
| 작업이 어디까지 왔는지 알기 | 화면 간 공통 상태와 마지막 변경 시각을 표시하고, 실제 보고된 진행 단계만 보여준다. 하위 에이전트의 실행·오류도 함께 판단한다. |
| 질문 사이를 오가며 답하기 | 미전송 답변과 추가 지시 초안을 유지한다. 응답 전달 결과를 알리고 다음 질문 또는 입력창으로 키보드 포커스를 잇는다. |
| 결과를 확인하고 다시 수정하기 | 결과물을 기본 탭으로 연다. 최신/이전 최종 답변, 해당 실행의 명령 종료 코드와 변경 파일을 연결한다. 앱은 새 탭에서 연다. |
| 이전 작업으로 돌아가기 | 프로젝트/앱별 저장 작업을 검색한다. 새 작업이 생겨도 이전 최신 결과를 별도로 보여주며 최근 200건 밖의 결과도 조회한다. |
| 앱의 운영 정보를 찾기 | 개요·작업 결과·문제 관리·사용량·예산·연결 설정 탭으로 분리했다. 문제 등록과 예산 편집은 대화상자에서 수행한다. |
| 필요한 자료와 세부 설정 열기 | 첨부는 입력 자료 대화상자로, 개발 환경 관리와 실행 기술 정보는 펼침 영역으로 이동했다. 템플릿은 대상·모드·권한을 확인한 후 실행한다. |

작업실은 대화 40%·결과 60%로 시작하고, 구분선을 포인터나 방향키/Home/End로 조절한다. 1280×800에서도 질문의 선택지·직접 답변·제출을 같은 영역에서 다룰 수 있도록 요청 영역을 우선했다. 상태 복구 안내는 작업실 위에 배치하여 결과나 입력창을 덮지 않는다.

## 결과와 상태의 근거

- 결과는 저장된 최종 답변을 읽는다. 명령 종료 코드 0을 전체 요구사항의 검증 성공으로 바꾸지 않는다. 근거가 제한되면 제한되었다고 표시한다.
- 이전 결과의 완료 시각이 없으면 미확인으로 남긴다. 작업의 최근 수정 시각을 이전 결과의 완료 시각으로 사용하지 않는다.
- 앱 링크는 연결 정보이며 작업 완료나 운영 배포 완료를 뜻하지 않는다. 작업 환경 링크는 해당 작업의 workspace/app/project 식별자가 일치하고 실행 관측이 준비된 경우에 표시한다.
- 기존 SQLite에 읽기용 요약과 결과 조회를 추가했다. DB 마이그레이션·새 실행 권한·새 인증 경계는 추가하지 않았다.
- 카탈로그의 최신 작업과 최신 결과는 별도로 계산한다. 계획 검토가 남은 오래된 작업도 계속 추적한다.

## 근거와 적용 한계

2026년 공식 사례와 최신 UX 자료의 출처·날짜·적용 판단은 [기존 검토 보고서](WORKBENCH_UX_REVIEW.md)에 보존했다. 사용자가 요청한 링크 확인 방식을 적용했으므로 다른 AI 빌더의 내장 미리보기 방식은 가져오지 않았다. 2027년 방향은 미래 가설이며 검증된 사례로 표현하지 않는다.

화면 인수와 자동 접근성 검증은 로컬 프런트엔드와 테스트 API에서 수행했다. 실제 구독 에이전트 장시간 실행과 외부 앱의 실제 접속 가능성은 이 검증 결과에 포함하지 않는다. 기존 변경 사항은 보존했으며 배포 당시 소스 변경은 미커밋 상태였다. 별도 배포 확인 범위는 아래 기록으로 구분한다.

## r25 배포 확인

사용자의 `배포` 요청으로 `20261012-workbench-ux-r25`를 설치했다. 기준 소스는
`b13a75741d16a83955ca928d50a548abace5c7b7`이며 검증한 미커밋 변경을 포함한다.
릴리스는 `source_dirty=true`로 표시하며 산출물 digest는
`sha256:2e8f4452c0912cfb8e17fac9c5ae1ae3faa35be6e632b47c6e04466a7f897677`이다.

- root/하위 작업과 자원 lease가 0건임을 확인했다. 공식 SQLite online backup과 무결성 검사를 수행하고 이전 r24·백업을 보존했다.
- migration·의존성 lock·native/SDK pin 입력이 이전 릴리스와 동일한지 확인했다. DB migration 없이 세션·관리 서비스를 전환했다.
- 두 서비스의 실제 실행 디렉터리가 r25이며, 템플릿 릴리스 링크와 템플릿 서비스 PID는 유지했다.
- 기존 프로젝트·작업 환경·계획·대화 항목·첨부·템플릿·문제·예산·앱 소스·등록 intent의 내용 해시가 배포 전후 동일했다.
- 직접 세 역할과 공개 주소의 health check가 통과했다. 공개 JS/CSS가 새 릴리스 파일과 바이트 단위로 일치하고 새 UX 스타일을 제공한다.
- 공개 Studio·앱 관리·작업 기록·템플릿·지침·모니터링·플랫폼 경로의 로그인 화면과 브라우저 오류 없음, 보호 API의 인증 거부를 확인했다.
- 새 릴리스 코드로 실제 저장 작업 19개의 요약·상세 스키마와 저장 결과 20건, 앱/프로젝트 활동 조회를 읽기 전용으로 검증했다.

배포 전 검사에서 단위 테스트 242개·타입·생성 계약·Ruff·starter 계약과 릴리스 빌드가 통과했다.
전체 API 검사 최초 실행은 1,390개 통과·25개 skip·1개 다중 프로세스 응답 시간초과로 종료됐다.
제품 코드나 검사 조건을 변경하지 않고 해당 파일을 재실행해 7개 통과·10개 환경 의존 skip을 확인했다.
브라우저 최초 실행은 39개 통과했으며, 같은 제목을 가진 프로젝트/작업 화면의 전환을 잘못 기다리던 검사 1개는
작업 URL 대기 조건으로 보완해 통과했다. 등록 권한 검사 3개도 통과했다. 최초 실패 로그를 보존하며 전체 CI 명령이 한 번에 통과했다고 보고하지 않는다.

운영 브라우저의 저장된 로그인 세션은 만료되어 로그인 이후 화면을 직접 검증하지 못했다.
비밀번호 변경이나 인증 우회는 수행하지 않았다. 로컬 79개 화면 인수를 운영 로그인 인수로 해석하지 않는다.
배포 영수증·검사 로그·공개 파일 대조·실제 DB 조회 결과는 비공개 `.runtime/workbench-ux-deployment-20261012/`에 보존한다.

## r26 카드 목록 배치 수정

사용자가 지적한 문제는 ‘내 확인이 필요한 작업’의 좁은 열에 여러 카드가 쌓여 내부 스크롤이 생기고 오른쪽 공간이 비는 배치였다.
데스크톱의 두 영역을 고정 두 열로 배치하고 목록 높이를 340px로 제한했던 스타일을 수정했다.
확인할 작업과 진행 중인 작업은 각각 본문 전체 폭을 사용하며, 각 목록의 카드는 화면 폭에 따라 여러 열로 펼친다.
목록 내부의 높이 제한·세로 스크롤은 제거하고 긴 목록은 본문 스크롤로 탐색한다.
