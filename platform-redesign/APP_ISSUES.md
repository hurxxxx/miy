# 앱별 후속 이슈 대장

2026-10-07 사용자 요청으로 신설했다. **별도 지시 전까지 기록만 유지한다.** 구조 완성에 필수인 변경과 치명적 문제는 [PLAN.md의 기준](PLAN.md#구조-완성-우선과-앱별-후속-작업)에 따라 현재 구조 작업에서 처리한다. 이 대장은 앱별 비필수 개선·세부 기능 검증의 단일 원본이다.

플랫폼·Workbench의 고급 UX·모니터링·평가·부하 측정·저장 프로토콜 확장은 [후속 고도화 작업](FOLLOW_UP_ENHANCEMENTS.md)이 소유한다. 앱별 항목은 여기 유지하며 두 문서의 보류 항목을 이번 구조 완료의 의존성으로 추가하지 않는다.

## 기록과 착수

- 발견 사실만 기록하고 `확인된 결함`, `의심/미확인`, `검증 대기`, `개선 제안`을 구분한다. 상세 검사를 하지 않았다는 이유로 결함으로 단정하지 않는다.
- 기본 상태는 `deferred`다. 구조 작업이 끝나거나 일반적인 “계속” 요청이 와도 자동 착수하지 않는다. 해당 앱/이슈의 별도 조사·개선·테스트 요청을 받으면 그 요청과 허용 범위를 기록한다.
- 기록을 위해 새로운 상세 조사·재현 테스트·제품 수정을 추가하지 않는다. 현재 알고 있는 근거와 영향만 남긴다. 이미 통과한 회귀 결과나 고친 문제를 미해결 결함으로 재등록하지 않는다.
- 구조 필수 또는 치명적 영향이 새로 확인되면 근거와 연결할 `WORK_ITEMS.md` 작업을 기록해 현재 범위로 전환한다. 중요도를 낮춰 필수 검사 실패를 보류하거나 숨기지 않는다.
- 아래 항목은 **앱 전체의 추가 인수 검증이 남았다는 기록**이며, 이미 수행한 구조·집중 회귀 검사가 실패했다는 뜻이 아니다. 앱별 세부 실행 계획은 별도 요청을 받은 뒤 작성한다.

## 새 항목의 최소 기록

`APP-ISS-007` — 2026-10-07, Meeting picker 개발 모드 검사 · 검증 대기 · `deferred`. PMS 부모 통합을 넓힌 actual-dev 실행에서 기존 picker 검사가 목록 GET 두 번을 기대했으나 같은 `?scope=all` 네 번을 관측했다. 포털/공식 production에서는 해당 검사까지 모두 통과했고, 개발 root는 기존 StrictMode를 유지한다. 클릭·연결·링크·두 번째 열기까지 진행한 뒤 정확 read-count assertion에서 실패했다. 이는 개발 모드 effect replay와 일치하는 관측이며 제품 결함 확정이나 HTTP 부하 인수는 아니다. `.runtime/pms-module-integration/dev-browser.log`와 trace를 보존했다. PMS 새 다섯 구조 경로는 이 실행에서 모두 통과했다. 앱 구현·대화/녹음 구조·쓰기 권한·mutation 횟수를 바꾸거나 이 실패를 통과로 표현하지 않는다. Meeting 개발 모드 상세 검증의 별도 지시 전까지 추가 조사·수정하지 않는다.

`APP-ISS-008` — 2026-10-07, 공용 Chatbot 기존 lint 경고 · 개선 제안 · `deferred`. `.runtime/files-module-extraction/owned-platform-lint.log`의 13개 경고를 그대로 보존한다. `HtmlArtifact.spec.tsx`와 `html-preview-bundle.ts`의 non-null assertion 각각 5개, `HtmlArtifact.tsx`의 `useMemo` 의존성 한 개, `useChatbotApprovals.ts`의 `useCallback` 의존성 두 개다. 위치는 현재 `packages/platform-web/src/chatbot/` owner이며 기존 본문 동등성으로 상속 경고임을 확인했다. 현재 린트 오류·필수 구조 검사 실패나 확인된 업무 결함으로 바꾸어 적지 않는다. HTML bundle/cache·preview channel·대화별 callback identity를 바꿀 수 있어 임의 정리는 하지 않았으며, 별도 요청 전 추가 조사·수정·세부 검증을 하지 않는다.

```text
ID / 발견일 / 앱:
종류: 확인된 결함 | 의심/미확인 | 검증 대기 | 개선 제안
현상 또는 미검증 범위 / 이미 있는 근거:
영향 / 구조 필수·치명적 문제에 해당하지 않는 판단:
상태: deferred

```

공식 서비스/원본 writer·worker 분리, native 격리 실행, 전체 자연어 개발 흐름, 동적 등록·독립 배포·권한·데이터 보존의 남은 검증은 후속 앱 이슈로 넘기지 않는다. 해당 작업의 원본은 [WORK_ITEMS.md](WORK_ITEMS.md)다. Workbench의 이미 합의한 세션·에이전트 UX도 현재 목표를 유지하며 요청하지 않은 추가 꾸미기만 같은 보류 기준을 적용한다.
