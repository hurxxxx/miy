# 재설계 지침 적용과 전환 기준

이 문서는 사용자가 요청한 재설계 범위에서 기존 지침·스킬을 대체하기 위한 기준이다. 2026-10-10부터 `POL-001`~`POL-003`은 [이번 필수 변경 경로](PLAN.md#이번-범위)에 한정하고 전역 정리·반복 평가는 [후속 고도화](FOLLOW_UP_ENHANCEMENTS.md)의 ENH-003으로 보류한다. 기존 하네스·스킬은 작업 절차로 적용하지 않으며 핵심 계약 보존과 실제 충돌 해소에 필요한 범위만 읽는다. 현재는 문서 범위 조정이며 구현 중단을 유지한다.

## 적용 원칙

1. 시스템·개발자 지침과 최신 사용자 요청의 범위를 따른다. 현재 요청은 필수 구조 범위 확정과 후속 고도화 문서 분리이며 구현·검증·게시·운영 배포 중단은 유지한다.
2. 이번 재설계의 목표 판단은 [PLAN.md](PLAN.md)와 사용자가 정한 적용·제외 기준을 따른다. 기존 구조를 전제한 규칙이 새 목표를 되돌리는 근거가 되지 않게 한다.
3. 현재 코드·테스트는 구현 사실과 호환성을 확인하는 자료다. 기존 경로·배포 방식이 존재한다는 이유만으로 새 구조에 강제하지 않는다.
4. 기존 스킬을 이번 작업의 수행 지침으로 로드하지 않는다. 특수 기능의 실행 계약과 고유 도구는 필요한 범위에서 보존하고 일반 개발 절차는 제거한다. 스킬 이름의 언급이 다른 스킬 전체를 연쇄 로드하는 이유가 되지 않는다.
5. 충돌은 원본 규칙, 적용 대상, 대체 기준, 검증 방법을 기록하고 해당 지침을 수정한다. 인증·권한·검증 우회로 해결하지 않는다.
6. 2026-10-10 요청에 따라 검증은 [최종 통합 검증 원칙](VALIDATION.md#2026-10-10-검증-일괄-수행-원칙)을 따른다. 남은 구조 구현을 최대한 통합한 뒤 검사를 한 번에 수행하며, 이전 스킬·이력의 검사 목록이나 별도 리뷰 순서를 기능마다 반복하지 않는다. CI가 다루는 전체 검사를 로컬에서 중복 실행하지 않는다. 필수 계약을 유지하며 릴리스 CI는 최종 후보에 집중한다. 현재 구현은 중단 상태다.

구현은 경로별 조사→필요한 전환→회귀 평가로 진행한다. 전역 `POL-001`~`POL-003`의 전체 완료를 모든 작은 수정의 선행 조건으로 삼지 않으며, 관련 경로의 미해결 충돌은 먼저 해소한다. 적용 결과는 [WORK_ITEMS.md](WORK_ITEMS.md)의 해당 작업과 [검증 근거](VALIDATION.md)에 연결한다.

작업 선택은 [PLAN.md의 구조 우선 기준](PLAN.md#구조-완성-우선과-앱별-후속-작업)을 따른다. 앱별 비필수 개선·상세 검증은 [APP_ISSUES.md](APP_ISSUES.md)에만 남기며 별도 사용자 지시 전까지 조사·테스트 추가·수정을 자동으로 시작하지 않는다. 기존 문서의 포괄적인 “앱 검증”이나 과거 검사 목록을 근거로 이 범위를 다시 넓히지 않는다. 구조 필수·치명적 문제의 수정과 필수 검증은 유지한다. 에이전트에 위임할 때도 구조 목적·변경 경계·필수 검사와 발견 사항의 기록 경로를 전달한다.

## 승인된 하네스 최소화 범위

- 특수 기능만 유지한다: `miy-app-delivery`, `miy-ai-capabilities`, `miy-dev-environment`, `miy-env-contracts`, `miy-docs-reader`, `miy-release`, `miy-production`. 각 스킬은 고유 도구·경계·소유 문서 연결에 집중한다.
- 일반 절차 스킬인 `agent-browser`, `diagnose`, `miy-design-review`, `miy-issues`, `miy-worktrees`, `miy-mr-review`, `miy-agent-harness`를 활성 카탈로그에서 제거한다. 일반 브라우저·Git·검토 기능 자체를 없애지 않는다.
- `SessionStart`, `PostToolUse`, `Stop`의 자동 스냅샷·검사·차단/재시도는 제거한다. `PreToolUse`의 Git 메타데이터·생성 파일 직접 패치 보호와 native 명령 규칙을 유지한다.
- 검사기는 실제 존재하는 스킬의 유효성과 링크·브리지를 확인한다. 정해진 14개 목록이나 특정 절차 문구를 강제하지 않는다. 제품·권한·생성 계약·릴리스 검사는 유지한다.
- 평가의 중심은 결과와 권한 경계다. 스킬 선택·토큰·시간은 관측값이며 경량화가 무조건 품질을 높인다고 가정하지 않는다.
- 템플릿 전환은 변경하지 않은 기본값만 자동 수정한다. 사용자 수정과 과거 snapshot은 보존하고, 삭제된 스킬과 변경된 참조를 실행/재개 시 명시적으로 다룬다.

## 유지할 공통 경계

- 인증, 사용자·실행 주체, 현재 앱 사용 권한과 원본 데이터 ACL은 서버가 확인한다.
- 비밀정보와 운영 데이터는 개발 환경·진행 문서·로그에 노출하지 않는다.
- 공유 플랫폼 상태는 PostgreSQL·객체 저장소를 사용한다. 단일 소유자 Workbench의 SQLite 예외는 유지한다.
- 제품 AI는 등록된 공통 실행 경로를 사용한다. 소유자 운영 Codex의 구독 인증과 제품 AI 실행은 구분한다.
- 외부 파일·URL, 자원 사용, 재시도·중복 실행·복구 경계를 검증한다.
- 기존 사용자 변경을 보존하고 수행하지 않은 검사나 관측을 성공으로 기록하지 않는다.
- 기존 구조를 강제하는 검사는 새 경계 검사로 대체한다. 기능 변경을 통과시키기 위해 검사 전체를 끄거나 보안 검사를 약화하지 않는다.

## 실행 계약과 증거의 적용

- native API 연동은 기존 버전·소비 스키마 검사를 재사용하고, 새 RPC의 지원 상태·실행 위치·권한을 확인한다. 미지원 기능을 별도 agent loop나 호스트 권한 우회로 구현하지 않는다.
- 소유자용 코어 관리와 현업 앱 개발의 실행 범위를 구분한다. 앱 저장소의 개발 환경 설정을 호스트 명령·마운트·자격증명 접근 권한으로 그대로 신뢰하지 않는다. 세부 경계는 [PLAN.md](PLAN.md) 4절을 따른다.
- 앱 manifest의 요청 권한, 자연어 템플릿, 저장소 문서는 실제 실행 권한을 부여하지 않는다. 앱 세션의 범위·수명과 권한 철회는 서버에서 적용한다.
- 배포와 복구는 검증 주체가 남긴 대상·버전·결과를 사용한다. LLM의 완료 선언이나 체크리스트 표시를 성공 근거로 대체하지 않는다. 명확한 기존 사용자 요청과 권한을 다시 묻는 절차를 추가하지 않는다.
- 검증을 수행하는 코드와 권한 검사는 생성 앱이 임의로 바꿔 통과시킬 수 없게 한다. 결과·권한·대상은 결정적 검사, 자연어 유용성은 기준과 표본 검토로 확인한다. 평가 절차의 소유 문서는 [VALIDATION.md](VALIDATION.md)다.

루트 및 영향받는 하위 `AGENTS.md`, `CLAUDE.md`, Copilot 연결 문서, 스킬 트리거·참조, 훅과 CI가 같은 적용 범위를 가리키게 한다. 문서 폴더 안의 지침만으로 소스 작업 경로에 정책이 적용된다고 가정하지 않는다.

Codex의 공식 스킬 발견·암묵적 선택을 고려한다. 템플릿 체크 해제만으로 기존 스킬을 제외했다고 보지 않으며 실제 실행 환경의 발견 상태와 선택을 확인한다. 전체 지침·스킬 처리나 agent loop를 별도로 재구현하지 않는다.

새 정책은 새 세션에서 검증한다. 진행 중 작업은 정책·하네스 버전을 기록하고 재개 시 변경 여부를 확인한다. 파일 목록이나 UI 표시만으로 기존 세션에 새 지침이 주입됐다고 주장하지 않는다.

현재 의도·대상·허용 범위·완료 기준을 기본 맥락으로 제공하고 세부 지침·계약은 필요할 때 읽는다. 지침·템플릿·SDK 버전과 접근 가능한 원본을 연결한다. 지원되는 native 지침 출처 정보와 실제 스킬 발견·선택을 관측하되, 결과가 새 구조·요청 범위를 지켰는지 별도로 평가한다. 재개 시 정책 변경과 진행한 작업의 충돌을 확인하고 중복 실행 없이 이어 간다.

작은 유지보수에 전체 명세 절차·전체 앱 이전을 강제하지 않는다. 명세와 구현에서 얻은 사실은 각 소유 문서에 맞춰 갱신한다. 조사 기록인 `REVIEW.md`를 최신 목표 설계의 별도 원본으로 사용하지 않는다.

## 충돌 처리와 종료

충돌이 발견되면 원본 규칙과 대체 범위를 `WORK_ITEMS.md`의 해당 작업에 연결하고, 주요 결정은 `PROGRESS.md`에 기록한다. 목표·권한·데이터 영향이 달라지는 경우에만 추가 사용자 결정이 필요한 사항으로 남긴다.

이행이 끝난 규칙은 원본 소유 문서와 검사기에 반영하고 임시 예외를 종료한다. 기존 ADR 전체를 폐기하지 않고 변경된 결정의 대체 관계를 루트 ADR에 기록한다.
