# 후속 고도화 작업

2026-10-10 사용자 요청으로 이번 필수 구조 변경에서 분리했다. **모든 항목은 `deferred`이며 별도 사용자 지시가 있을 때 착수한다.** 이번 구조 작업의 완료나 일반적인 “계속” 요청은 고도화 착수 지시로 해석하지 않는다.

이번에 반드시 할 일은 [PLAN.md의 필수 범위](PLAN.md#이번-범위), 진행 상태는 [WORK_ITEMS.md](WORK_ITEMS.md)가 소유한다. 이 문서는 플랫폼·Workbench의 후속 고도화 범위를 소유하며, 앱별 기능 개선·상세 테스트는 기존 [APP_ISSUES.md](APP_ISSUES.md)에 남긴다. 이미 구현·배포한 기능과 검사 결과를 취소하거나 실패로 바꾸지 않는다.

## 조건부 항목을 다루는 기준

ENH-005/006의 전체 설계를 이번 구조의 필수 조건으로 취급하지 않는다. 현재 트랜잭션·단일 저장 주체·공통 저장 서비스·공개 확장점의 재사용으로 분리와 안전성을 확보할 수 있는지 먼저 판단한다. 같은 DB 서버의 사용이나 공통 저장 서비스의 재사용 자체는 네 영역 분리 실패가 아니다. 실제 인증·권한·데이터 소유와 독립 변경·배포 경계는 유지한다.

새 저장 프로토콜을 도입하지 않으면 특정 서비스 분리가 불가능하거나 구체적인 권한 우회·데이터 유실·중복 쓰기가 남는다는 코드/실행 근거가 있을 때만 **그 문제를 해결하는 최소 부분**을 이번 작업으로 연결한다. 문제, 영향 경로, 기존 경로로 해결할 수 없는 이유, 최소 수정·검증을 해당 `WORK_ITEMS.md` 작업과 런타임 소유 문서에 기록한다. 전체 고도화 항목을 자동으로 현재 범위에 편입하지 않는다. 이미 확인된 치명적 결함을 보류 항목으로 숨기거나 필수 실패 검사를 면제하지 않는다.

현재 C2 journal/adapter와 Files 관련 미게시 후보·검증 자료는 보존한다. 이번에 채택하지 않은 후보의 독립 리뷰·모델 실행·실제 통합을 추가 진행하지 않는다. 보존만으로 게시·배포·활성화하지 않으며, 나중에 사용할 때 당시 코드·계약·환경에서 필요한 검증을 판단한다.

## 나중에 착수할 때

사용자가 지정한 항목의 현재 필요성과 선행 구조를 확인하고 그때의 구현 범위·완료 기준을 정한다. 기존 자료는 참고 근거이며 과거 검사 횟수·별도 리뷰 순서·전체 계획을 그대로 다시 실행하지 않는다. 상태 변경과 실제 결과는 이 문서의 해당 항목에 연결한다.
