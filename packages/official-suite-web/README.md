# Official UI source

`@miy/official-suite-web/whiteboard` owns the complete Whiteboard module: API and scene codecs, editor and collaboration implementation, hub/picker/context panels, sharing UI, models and Excalidraw library assets. The lazy public cross-app API preserves its component/function identities through the former web exports. `/whiteboard/module` owns routes/sidebar/composition, with the same canonical paths and admission behavior. Meeting and PMS consume the public entry; private source imports stay restricted to the owner and existing compatibility adapters. Shared realtime/directory/user-picker implementations belong to platform-web. The portal retains its single live realtime Provider; the stage-zero suite supplies the same Context through one offline Provider (`token=null`) without platform realtime traffic. Each root owns auth/i18next initialization. The existing library tests move with the source, while the two Korean root-catalog integration specs stay in web and exercise the compatibility entries. This is source ownership, not separate service activation or independent release readiness.

The official suite owns this source library. Its public `@miy/official-suite-web` entry exports the twelve official app manifests, their ordered `OFFICIAL_APP_MANIFESTS` projection and `OFFICIAL_HELP_GUIDES`. `@miy/official-suite-web/diagrams` exports the actual Diagrams UI, with its API client, hub model and draw.io protocol owned here. `@miy/official-suite-web/bento` exports the Bento UI; its API client, route builders, embedded-editor protocol and AI job source are also owned here. `@miy/official-suite-web/mail` exports the Mail UI; its personal API client, account/draft workflow, message presentation and sanitizer belong here. Membership and ordering come from the shared app contract; no runtime allowlist or admission policy is defined here.

This is a private Nx source library, consumed through the repository TypeScript aliases and existing locked root dependencies. It has no separate package installation, published artifact or service. Metadata depends on contracts, core-web shell types and existing icons; Diagrams, Bento, Mail, Whiteboard, Community, Docs, Recording, Meeting and Planner use the actual [platform browser runtime](../platform-web/README.md) and existing `@miy/ui` components. It must never import either `apps/web` or `apps/official-suite`; the web architecture check enforces that direction and checks both UI roots for cycles.

The portal and suite roots consume its public help composition. Existing web implementation paths for all twelve official apps are same-object compatibility exports. Each app owns its complete route/sidebar/module implementation here; both roots consume public `@miy/official-suite-web/<app>/module` entries in shared contract membership/order. Files uses the actual public common Chatbot implementation in platform-web. The shared stylesheet scans both source libraries. Root auth, admission, i18next and shell/widget composition retain their existing lifetimes. This completes UI source ownership; portal composition cleanup, independent API/worker/service release and runtime cutover remain separate work. Authorization, app IDs, URLs and writer ownership are unchanged.

Diagrams list/editor state belongs to the current browser session. A token change remounts the view; obsolete list responses and completed writes cannot update or navigate the next session. Draw.io messages still require the current iframe window, configured exact origin and current edit permission. Server-side resource authorization remains authoritative.

Bento also keys its hub/editor state to the current login generation. Late list responses cannot replace a newer query or session, and an old create/import/archive completion cannot navigate the next session. Its [same-login save queue](../../docs/apps/bento/README.md#dataauth) drains captured edits during ordinary navigation using the shared platform session predicate; obsolete credentials stop unstarted writes. Import/AI follow-up requests still stop when their view is replaced, and already submitted writes retain server authorization and version checks. Its exact iframe origin/window, protocol v2 and current edit permission are preserved. The third-party runtime and `ops/bento/miy-bridge.js` stay in their existing deployment; the moved bridge test resolves that fixture from its own file rather than the caller working directory. Browser translations and Vite embed settings still come from the existing root composition.

Mail state is scoped to the current login and selected message/draft. Late list successes and failures cannot replace a newer query; summary and reply results cannot populate a different selection. Details are read only in the message view; returning to it reloads the selected message after an abandoned request. Account connection-test→create and draft save→send check that the originating view still exists before issuing their next request. Leaving the view or changing login does not cancel a send already accepted by the server, and its late result does not notify the next session. The API consumes the existing default `i18next` instance; only the portal/suite roots initialize it. Existing sanitization and the no-script/no-same-origin iframe sandbox remain unchanged: remote images are allowed by default, `no-referrer` remains set, and no CSP is newly introduced. Tests use synthetic adapters and HTML, without connecting external mail accounts or sending mail.

`@miy/official-suite-web/planner` preserves the narrow personal event CRUD API and `PlannerEventModal` entry. `/planner/module` now owns the complete aggregate calendar/timeline, floating widget, routes/sidebar and Meeting/PMS composition; `/planner/public-api` retains the former API-only surface. Existing web implementation paths export the same objects. The root keeps the personal dock, admission and single provider initialization, while Home and PMS consume public source entries. The library owns only Planner Korean/English messages; the roots compose them with unchanged values.

The event editor resets on login, event or selected create-range changes and disappears on logout. Pending save/delete results cannot update callbacks after their editor closes or is replaced; an already submitted server write is not cancelled or rolled back by this browser guard. Current-session save failures retain the draft for explicit retry. Empty state, date-only exclusive ends, optional times, server ACL and `/api/v1/planner/events` routes are unchanged. Focused checks cover CRUD, failure/retry, previous-session/closed/replaced-editor responses and web Planner/floating-widget callback projection.

`@miy/official-suite-web/video-chat` owns the room lobby and existing Video Chat API module. Its complete room and route composition now belongs to `/video-chat/module`, with the original lazy LiveKit/style imports and same public compatibility entries. Compatibility API exports preserve the exact error class/functions used by that room, with the same endpoints, request methods, current bearer, host locale and server authority. Both roots still use their existing router, AuthProvider and translations.

Lobby state resets on login changes and disappears on logout. Only the latest list request can replace rooms or report errors; an old create result cannot navigate a different session or a view that has already closed. Duplicate clicks while creation is pending are ignored. Current-session errors retain the room title for explicit retry. Pending clipboard results and copied-label timers are scoped to the current lobby. These browser guards do not cancel a room creation or clipboard write already accepted by its destination. Tests use synthetic HTTP/clipboard adapters and do not connect to a media server, request device permissions or consume real join credentials.

Run `pnpm nx test official-suite-web` and `pnpm nx typecheck official-suite-web`, then the web/suite focused composition tests and `pnpm check:web-architecture`. The suite transition and remaining service boundaries are owned by [the official suite](../../apps/official-suite/README.md).

`@miy/official-suite-web/meeting` retains the existing Meeting API/picker public surface. `/meeting/public-api` owns the full former public union of API/picker, insight API and permission display hints. `/meeting/module` owns the complete routes/sidebar/module with the same lazy `MeetingCreateModal` and `MeetingDetailLayout` wrappers consumed by Planner. All Meeting forms, availability/list/detail, collaborative notes, insights, recording controls and pure models now belong here. Old web paths are same-object exports; the narrow API entry does not import the module or screens. Existing API paths, bearer/locale handling, multipart requests, recorder/recovery hooks and UTC date parsing remain unchanged. Permission hints do not grant server access.

Only Meeting Korean/English messages belong to `/meeting/messages`; roots compose them with unchanged values and keep one i18next initializer, AuthProvider, admission Context and recorder mounts. Meeting uses existing public Docs/PMS/Whiteboard/Recording source. It imports the actual platform conversation/tool HTTP leaves instead of Chatbot's broad UI barrel; this changes no conversation creation, insight prompt, approval, provider/model choice or navigation. Chatbot UI, personal widgets and Files artifact composition remain in their existing owners. Eleven existing independent Meeting specs move here; the permissions spec retains its root company fixture. This completes Meeting source ownership, not an independently releasable service.

The picker consumes the single platform bootstrap Context and generic resource picker through public entries. Its own session resets on external close, login/user change or Meeting admission change; old picks cannot close a newer picker, expose an old error or invoke a retained callback after disposal. Shared Docs/PMS/Whiteboard picker behavior is unchanged. The current picker copy is intentionally Recording-specific. Recording's existing `void` selection callback still initiates its own attachment and closes without waiting: picker closure is not attachment-success evidence, and this source move does not fix the entire Recording controller's asynchronous mutation lifetime. Tests use synthetic HTTP and controlled callbacks without creating real meetings, uploading recordings or accessing media.

`@miy/official-suite-web/files` owns the Files manager/search workspace, folder tree/sidebar, upload provider/batch/model, image preview, Files RAG sources artifact and existing Files API. Its FilesChatView experience and route/sidebar/module now belong to this suite owner; the actual common Chatbot UI belongs to platform-web. Root initialization and shell/widget composition remain with their roots. The API endpoints, app/resource authorization, visibility/publication acknowledgement, search ranking, RAG polling and upload events are unchanged. Existing leaf paths re-export the same API/error and upload Context objects; both UI roots consume this single provider. Public Files artifacts may be embedded by the existing Chatbot composition without importing Chatbot back into this package.

The upload session survives folder navigation and is replaced on login change. Disposing it aborts the current transfer, stops unsubmitted files and suppresses obsolete progress/toasts/events. The manager scopes pending folder mutations, download/preview follow-ups and navigation to its login/folder; previews revoke discarded object URLs. The sidebar keeps only its latest current-session response, including errors. RAG artifacts discard old download follow-ups and 401/logout handling when their content or login changes. These browser guards do not undo server-accepted uploads/deletions/folder mutations or claim cancellation of a binary download already handed to the shared downloader. The existing search controller retains its request-generation/abort behavior.

Browser downloads and byte formatting use the actual public `@miy/platform-web/browser` and `/format` implementations. The image dialog is owned once by `@miy/platform-web/media`; host i18next initialization, accessible close controls, Escape handling and body-scroll cleanup remain unchanged. Tests use synthetic files, HTTP and object URLs; no real file store or customer document is accessed.

`@miy/official-suite-web/pms` owns the existing PMS browser API, filters, UI role hints, sidebar reorder model and TaskPicker with its pure model. The complete PMS list/board/calendar/Gantt/table/task-detail/floating implementation and existing route/sidebar/module composition now live here. `/pms/module` is the full composition entry; the existing narrow `/pms` entry stays unchanged so API/picker consumers do not eagerly import the full module. Existing public and leaf paths re-export the same functions and internal mapped error implementation; Docs, Home, Meeting, Planner and Recording consume the public suite entry. URLs, request bodies, pagination, host locale, CSV download and server authorization remain unchanged. `taskListRoleAllows` remains a display hint and never grants resource access.

The TaskPicker keeps the current login/user, open state, PMS admission and fixed-list lifetime. Changing its selected list also invalidates pending picks; late success/error and callbacks retained from a disposed picker cannot close or submit from a newer selection. Current errors remain available for explicit retry. The public `Promise<void> | void` callback is unchanged, and these browser guards do not cancel or undo an already submitted server mutation. Generic resource pickers and the existing Meeting/Recording copy wrappers retain their own behavior. Tests use synthetic list transports and controlled callbacks, including a real shared Dialog and the existing host contexts.

The generic ordered-sibling algorithm belongs to `@miy/platform-web/ordering`, shared by PMS and Docs. The PMS adapter preserves its existing flat reorder policy. The initial six PMS specs and the existing fifty-two remaining business specs live with their source; help routing, source compatibility and the linked-Docs publication-copy integration stay in web. The pure PMS test fixture is suite-owned. Product bodies, whole catalog values and old public objects are compared with the captured original. This source move adds no service, writer, permission, registry entry or independent release artifact.

`@miy/official-suite-web/community/module` owns the complete Community route/sidebar/module composition and lazy screen, with the existing API/cache, URL builders and channel constants. `/community` exposes the current API and URL helpers, `/community/editor` the Community Markdown editor/viewer and stylesheet, and `/community/events` the single channel-change event implementation. Admin Community settings consume those public entries. Old web paths export the exact same API/error/editor/event objects; there is no second channel cache or event listener. The existing HTTP routes, bearer/resource checks, current Markdown/upload behavior, channel defaults and navigation paths remain unchanged.

`/community/messages` owns only the Community Korean/English catalog. The root composes it with platform common/auth messages and its remaining catalog, with identical keys and values. The messages entry does not import the module or editor, so host localization does not eagerly load Milkdown. Community uses the common auth/media/date/realtime APIs and the host's existing AuthProvider and i18next singleton. The portal provides live realtime; the stage-zero suite supplies the same offline Context without connecting. Existing API/URL/manifest tests live here; the Korean Community screen test stays in web as a host composition test. This full module source move does not activate an official service or complete independent packaging/root ownership.

`@miy/official-suite-web/docs` owns the complete Docs UI implementation and the existing lazy cross-app viewer/picker API. `/docs/module` supplies its routes/sidebar/module, and `/docs/messages` supplies only the Docs Korean/English catalog. The former web paths re-export the exact API/error/functions/components; Home, Meeting, PMS and Recording consume the public entry. Shared auth, API, media, realtime, directory, ordering, picker and time implementations remain platform-owned. Root auth/i18next initialization and catalog composition are unchanged; importing messages or module metadata does not eagerly evaluate the Docs screen/editor. Existing fourteen source tests move with the owner; the publication-control ko/en integration test stays at the root. Snapshot deadlines, pending-content behavior, ACLs, HTML isolation and current lazy loading remain unchanged. This completes source ownership for Docs, not separate service activation or independent release packaging.

`@miy/official-suite-web/recording` owns the complete Recording UI, browser API, recorder/recovery/storage implementations and lazy cross-app public views; `/recording/module` owns routes/sidebar/module composition and `/recording/messages` owns only its Korean/English catalog. Old leaf/public exports retain the same API/error/class/component objects, including the TaskPicker default export. Meeting and PMS consume the suite public entry. The root retains its existing AuthProvider, i18next initializer and recorder component mounts; this source move does not initialize another recorder, change IndexedDB/session/local-storage lifetime, request device permission or alter uploads, recovery and attachment behavior. Existing eight Recording specs move with their source, while root compatibility/cross-app checks continue through both public paths.

The canonical fixed Service Worker asset belongs to `public/recording-sync-sw.js`. The narrow `vite/fixed-assets.mts` plugin is installed once in the shared web Vite config, inherited by the official root. It serves exact `/recording-sync-sw.js` GET/HEAD requests in development and emits that unchanged fixed filename/bytes in production. Query strings retain ordinary static-asset behavior; other paths are not mapped to files. Missing source fails with a bounded dev error or a build failure. Client registration keeps its original URL and default scope; there is no symlink, hashed worker URL or forwarding worker. The pinned Nx asset copier works in the build `writeBundle` hook and does not supply this fixed dev URL, so the fixed-asset plugin addresses that specific gap. `pnpm test:vite-source-aliases` checks both real root configs, Vite-served bytes/MIME/HEAD/errors and an in-memory fixture bundle. Parent integration validates each actual production artifact. This remains source ownership, not independent service activation.

`@miy/official-suite-web/calendar/*` owns the existing unified calendar API, source-specific event DTO/reducer/hook, FullCalendar wrapper/adapter and scoped theme CSS shared by Planner and PMS. These DTOs explicitly aggregate Meeting, PMS and personal Planner events, so they are official business source rather than a generic platform calendar engine. The same HTTP/error implementation, AuthContext, request-version guards, date offsets, FullCalendar plugins/locale and default mock option are retained; production callers keep their existing `useMockData: false`. Portal and suite roots import the same canonical CSS once. No event data, permissions, dependencies or time policy change. The original CSS and TypeScript paths remain compatibility entries, and the source-library model is not an independent service release.

`/pms/messages` owns only the PMS Korean/English app catalog; the root composes unchanged messages and retains shell publication/admission copy. Existing cold compatibility entries keep their prior host i18next initializer import, while the new suite source never initializes a host. The single fixed-asset plugin also owns canonical `public/help/pms/user-guide.html`, serving/emitting its unchanged `/help/pms/user-guide.html` path with HTML MIME. Both assets use exact fixed paths and GET/HEAD, preserve query behavior, and fail on missing source. The original `recordingSyncAsset` factory re-exports the same plugin factory; there is no second lifecycle or general path-to-file mapping. The manual exists once, with unchanged bytes and English section anchor.

`@miy/official-suite-web/files/module` owns Files routes/sidebar/main/search/chat composition. Its narrow `/files` API/upload/artifact entry is unchanged, and `/files/messages` owns only its exact Korean/English copy. Files chat consumes the existing common `@miy/platform-web/chatbot` experience contract and component, keeping its Files scope and artifact renderer under the official owner. It does not add a second Chatbot engine, choose a provider or grant access. Old paths preserve the same module, callbacks and UploadContext.

`@miy/official-suite-web/video-chat/module` owns the complete lobby/room routes and module. The existing narrow `/video-chat` lobby/API entry remains unchanged; room SDK/style imports stay behind the original lazy route. `/video-chat/messages` owns only the exact app namespace. Old room imports retain their prior host initialization. The room follows the existing lobby's numeric identity remount pattern for login and room changes; retired join/action completions cannot connect an obsolete credential, change the replacement screen or navigate after leaving. A refused refresh clears the previous credential. The pinned LiveKit SDK owns connection teardown; synthetic tests do not establish real provider/media behavior or cancel an accepted server action.
