# Shared browser platform

This Nx source library owns the actual browser `AuthContext`/`useAuth`, generated-contract-based browser auth types, HTTP client and user time preferences. The old `apps/web/src/platform/*` paths re-export these same implementations. Both UI compositions use `@miy/platform-web/*`; there is exactly one context instance, not a second session or an injected substitute API.

It also owns `date/DateInput` (`DateInput`/`DateTimeInput` and the existing date picker), `date/date-input-model` and `time/native-date-input`. The old web component/helper paths re-export these implementations. The host i18next instance, stored date format, local date/time interpretation, exclusive date ranges and keyboard/calendar behavior are unchanged. The shared root stylesheet explicitly scans this source library for its existing utility classes. This is browser presentation; it does not change server time-zone or calendar authorization rules.

The platform root still owns `AuthProvider`: login/logout, session storage, bootstrap/access refresh, desktop session synchronization and analytics lifecycle remain in `apps/web/src/platform/auth/auth-provider.tsx`. Authorization and app/resource admission remain server responsibilities. This library exposes the existing browser context and does not issue credentials or grant access.

The optional `AuthContextValue.isSessionCurrent` is a snapshot predicate for one browser credential generation. The real provider invalidates it synchronously on logout or session replacement, including the same token, and on rejected access or provider disposal; ordinary preference/access refresh keeps its identity. Retained callbacks can check it after an app view unmounts. It controls pending browser work, supplies no server authority, and cannot cancel a submitted request. Legacy contexts without it retain their consumer's mount-only guard.

`@miy/platform-web/apps` owns the actual shared app-bootstrap Context, its Provider/projection/admission hooks, generated-contract-based bootstrap types and `NoAccessNotice`. The old web Provider and hooks re-export the same objects; the shell still fetches and refreshes the snapshot through its existing `apps-api.ts`. Types are separated from that shell client, so neither this Context nor official app source imports a web API implementation or initializes another bootstrap lifecycle. The displayed app list is the current admission projection; navigation categories never grant access and the server remains authoritative.

`@miy/platform-web/pickers` owns the existing generic picker reducer/projection, load/session hooks and `ResourcePickerDialog`. Their former web paths are compatibility exports used by Docs, PMS and Whiteboard. They contain no business API or resource authority. Business callers own selection/mutation and session lifetime; the shared hook cancels old load results and invalidates picks on its own close/unmount, but does not infer login or resource ownership from arbitrary callbacks. The official Meeting picker adds its own open/login/admission lifetime. Existing shared stylesheet scanning covers these classes. No second UI/i18next/auth context is introduced.

The HTTP client and missing-provider error use the existing default `i18next` singleton. Each application entry initializes it before rendering or calling APIs; neither this library nor a business app initializes another instance or copies translation resources. JSON/binary requests retain existing token, locale, cancellation and error semantics. Time formatting/preferences retain their storage keys and account synchronization through the existing provider.

This is repository source consumed through public TypeScript aliases and existing root dependencies. It has no package manifest, independent installation, published artifact or service. `core-web` retains the headless registry/navigation helpers and shared shell metadata types. `platform-web` may depend on contracts and those types, but never application roots or business app implementations. The architecture check enforces this source direction and cycles across both UI roots.

Run `pnpm nx test platform-web`, `pnpm nx typecheck platform-web`, the web `shared-auth-context.spec.tsx`/auth/time focused tests, and `pnpm check:web-architecture`. The [Diagrams implementation](../official-suite-web/README.md) consumes this platform source; authenticated composition tests verify the old provider and new UI share the same context, locale and logout behavior.

Date checks include Korean/English text entry, invalid input, Enter/Escape, narrow viewport positioning and calendar-day arithmetic. Run the date tests with `TZ=America/New_York` as well as UTC to exercise spring/fall daylight-saving boundaries; timestamp conversion still follows the existing local-field contract. React component specs select jsdom per file while pure platform tests retain their Node environment.

`@miy/platform-web/browser` owns the existing authenticated content downloader and Blob/object-URL helpers; `@miy/platform-web/format` owns byte-size formatting. Their old web paths re-export the same functions, so Files, DM, Chatbot, Meeting, PMS, Recording, Whiteboard, Community and admin/media consumers keep a single implementation. Downloads still accept only the fixed `/api/v1/content#grant=…` capability URL and move the grant to `X-MIY-Content-Grant`; the host supplies the existing session bearer. Anchor/object-URL cleanup, binary error handling and the shared default i18next instance are preserved. These helpers do not initialize a host, select an account or confer resource access; caller lifecycle remains the business owner's responsibility.

`@miy/platform-web/media` owns the existing `FullscreenImageDialog`. It retains the optional close-label default from the host i18next common catalog and uses the existing UI cn helper. The old component path is a same-object re-export. This host-localized browser presentation belongs here rather than adding host localization to the copy-via-props UI primitives. Public props, accessible names, Escape handling, image/zoom composition and body-scroll cleanup remain unchanged.

`@miy/platform-web/ordering` owns the existing pure ordered-sibling/reparent algorithm used by PMS and Docs. The old web helper is a same-object compatibility export. Parent IDs, insertion positions, sort steps, no-op detection and the existing Korean text tie breaker are preserved. This module performs no network request or authorization and has no asynchronous mutation lifecycle. Business reorder adapters and server write checks remain with their respective owners.

`@miy/platform-web/routing` owns the existing lazy-route loading/error boundary and browser sidebar contracts. `@miy/platform-web/deployment` owns stale-asset recovery and its single cooldown state. Old web paths re-export those same objects, while each root retains its existing router/i18next initialization and startup handler installation. Moving the implementation does not install a second listener, add retries, change recovery timing or eagerly import business screens. Route metadata types belong to the existing core-web navigation contract; sidebar types use this platform’s AuthUser type without importing a root. Existing root lazy-route tests continue to verify Korean copy and navigation-reset behavior through the compatibility entry.

The shared Vite config uses explicit source-directory aliases for this library and official-suite-web, inherited by the official UI root. These private Nx source libraries need no node_modules symlink or package manifest. `node --test scripts/vite-source-aliases.test.mjs` checks their public entries with the actual Vite resolver independent of Nx’s startup-only tsconfig cache.

`@miy/platform-web/realtime` owns the existing realtime Provider, Context, hooks and WebSocket runtime. Old web paths export the same objects. Each application root retains its single Provider mount and token-driven connection lifecycle; importing this library does not connect a socket or initialize another runtime. Subscription shapes remain in contracts and server access checks remain authoritative. `@miy/platform-web/directory` and `/users` own the existing directory API/picker and user option picker/model. Their HTTP paths, permissions, debounce/cancellation and selection behavior are unchanged. Whiteboard consumes these public platform entries; Docs, PMS, Meeting and admin retain compatibility entries to the same implementations.

`@miy/platform-web/auth-api` owns the existing browser authentication HTTP adapter, system-role display helpers and `AuthApiError`. Former web imports re-export the same functions and class; the old auth entry retains its explicit host-initializer import for compatibility. The actual AuthProvider remains in the application root and owns login/logout, storage, access refresh and desktop synchronization. This move does not grant access or introduce another session lifecycle.

The existing media HTTP adapter, `useMediaUpload` and per-token media URL resolution session are now owned by `@miy/platform-web/media`. Their existing paths, FormData, resource-link behavior, error handling, cache/object-URL disposal and callback signatures are unchanged. The hooks consume this library's single AuthContext and HTTP error class. `@miy/platform-web/date/UserDateTime` owns the existing component and formatter, using the same account preferences and time implementation. Root compatibility paths export the same objects for Community, Docs, PMS, Meeting, Video Chat and admin consumers.

`@miy/platform-web/i18n` owns locale validation/storage/session helpers and `syncLocale`, and exports the default i18next singleton without initializing it. `/i18n/resources` owns only common/auth Korean and English messages. Each application root still imports its existing single initializer, which composes these messages, the official Community catalog and the remaining host catalog before rendering. Community messages belong to the suite; the mixed remaining business catalog has not been moved into the common platform. Cold imports of common APIs do not initialize a host. Compatibility entries preserve singleton/function identity, locale storage keys, fallback, pluralization and interpolation.

`@miy/platform-web/apps/app-links` owns the existing pure app navigation query helpers; `/network/request-concurrency` owns the existing bounded request limiter. Compatibility paths export the same functions. Navigation route types come from core-web, without importing an app manifest or root. The request limiter's ordering, concurrency, error and promise behavior are unchanged; it adds no scheduler, session lifecycle or retry policy. Its existing pure spec moves with source, while the app-links test that composes the official Docs manifest stays in the web root.

`@miy/platform-web/form/FormDialog` owns the existing copy-injected form composition over `@miy/ui`; `/users/remote-user-search-session` owns the existing generic debounced request hook used by Meeting and DM. Previous paths export the same components/hook. Props, input styles, callbacks, debounce/abort behavior and existing lifecycle remain unchanged. Neither introduces an app-specific form or scheduling engine.

The narrow `/ai/ai-api`, `/ai/conversations-api` and `/ai/hermes-agent-api` entries own the existing browser tool/conversation/Hermes transport implementations. They use the same API client/error mapping, generated contract types and default i18next object, and never import an application root, official UI or Chatbot view. HTTP bodies/routes, human bearer, approvals, history/preview parsing and error/function identities are unchanged; these adapters do not choose a runtime provider/model or add AI authority. Old web transport shims preserve their original host-i18n cold-import side effect. New common imports remain inert until the existing root initializes the singleton. Common `apps.ai`/`apps.hermesWorkspace` messages now belong to the inert Chatbot messages leaf, while each root composes and initializes the same singleton. The Files artifact renderer remains official-owned. The unused Meeting scope-title helper is preserved with its official owner and type-only common binding.

`/time/korean-holidays` owns the existing synchronous holiday lookup and its single warning cache; `/theme/app-color-fallbacks` owns the existing fallback constants; `/personal-widgets/floating-panel-events` owns the existing shell event names, detail types and dispatcher. Legacy exports retain the same functions/constants/cache. These helpers import no business implementation and change no years, locale, time-zone policy, event payload, admission or lifecycle. The personal dock and its storage/API remain with the root. Unified calendar business DTOs and FullCalendar composition belong to official-suite-web/calendar, not to this common runtime.

`/routing/shell-navigation-model` owns the existing pure shell path/query/manifest resolver, using core-web navigation helpers and types. Old web exports and the routing public entry reference the same functions; no second route registry, app-ID switch, root import or runtime initialization is introduced. The manifest-based integration test remains in web, while PMS consumes the shared public implementation.

`@miy/platform-web/chatbot` owns the existing shared conversation/stream/approval/artifact/Hermes workspace UI and its narrow public experience contract. `/chatbot/module` supplies the existing platform app routes/sidebar/module; `/chatbot/manifest`, `/chatbot/state-types` and `/chatbot/messages` are inert public leaves. Files consumes the public component with its own registered scope and renderer. The sidebar Portal retains one Map/Set and host/controller objects; old exports preserve those identities and their original cold host initialization. Root Auth/admission/i18next, storage/session/SSE, generated HTML sandbox/CSP and SVG policy are unchanged. Shared Markdown/Document artifacts, Hermes terminal HTTP and SSE parsing also have single public common owners. Existing KaTeX/highlight CSS and bundler fonts/wasm resolution remain pinned; this library does not initialize a host, connect a provider, decide app authority or add a chat engine.

Chatbot's existing `esbuild-wasm/esbuild.wasm?url` bundle asset, HTML bundle cache and assistant-ui dependency remain unchanged; there is no second bundle engine or fixed asset server. Existing twenty-nine independent Chatbot specs and the terminal API spec now live with their common owners. The canonical locale helper is test-only and outside product source. Root cold transport integration stays with host initialization. The unused Meeting conversation scope-title helper is preserved with its official owner, using `/chatbot/state-types` only, and is not newly invoked.
