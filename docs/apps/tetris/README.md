# 테트리스

개인 앱에서 실행하는 단일 플레이어 블록 게임이다. 실행 경로는 `/apps/tetris`이며,
기존 OWH Web/API와 함께 설치한다. 수동 플레이에는 별도 프로세스·포트·외부 서비스·AI 인증이 필요 없다.
AI 플레이는 기존 공통 판단 모델 연결을 사용한다.

## 설치와 앱 활성화

[개발 환경 설치](../../../INSTALL.md)를 완료하고 앱 등록 계약이 포함된 API·Web을 실행한다.
플랫폼 관리자가 **관리자 설정 → 앱 사용/접근 설정 → 테트리스**를 켜고 사용할 사용자 또는
그룹을 선택한다. 새 앱의 기본 상태는 비활성·선택 대상이며, URL을 안다고 접근할 수는 없다.
활성화와 대상 설정 후 **개인 앱 → 테트리스**에서 연다. 실행 중인 브라우저는 새로고침해
최신 앱 목록을 가져온다. 회사 전체 허용은 관리자가 별도로 선택하는 정책이다.

앱 ID `tetris`, 개인 실행 범위와 개인 리소스 범위는
[앱 등록 계약](../../../packages/contracts/app-contracts.json)이 소유한다. 서버 bootstrap의
앱 허용 결과와 기존 shell 라우팅을 사용하며 게임이 별도 접근 허용 목록을 만들지 않는다.
운영 서버 반영은 [릴리스 절차](../../domains/release/README.md)를 따른다.

## 조작과 게임 상태

- **게임 시작**으로 시작한다. 방향키 좌우로 이동하고 아래쪽으로 빠르게 내린다.
- 위쪽 방향키 또는 X는 시계 방향, Z는 반시계 방향 회전이다.
- Space는 즉시 떨어뜨리기, C는 블록 보관이다. 한 블록을 놓기 전까지 보관은 한 번만 가능하다.
- P 또는 Esc로 일시정지·재개한다. 화면의 이동·회전·보관·내리기 버튼으로도 조작할 수 있다.
- 점수·제거한 줄·레벨과 다음 블록·보관 블록을 표시한다. 블록은 색상과 문자로 구분한다.
- 창·탭·게임 밖으로 포커스가 이동해도 게임과 AI 플레이는 계속된다. 멈추려면 **일시정지**
  버튼이나 보드에 포커스를 둔 상태에서 P/Esc를 누른다. 다른 입력란의 키는 가로채지 않는다.
  브라우저가 백그라운드 탭의 실행을 제한하면 게임과 AI 요청 간격도 늦어질 수 있다.
- **다시 시작**은 현재 게임을 초기화한다. 다른 앱으로 이동하거나 페이지를 새로고침하면
  플레이 상태와 점수가 초기화된다. 진행 중인 게임은 일시적인 화면 상태이며 서버 저장,
  순위표·사용자 간 공유·브라우저 저장소 보관 기능은 없다.

## AI 플레이

관리자는 [판단 모델 설정](../../domains/ai/gateway.md#decision-workloads)에 따라 OpenRouter의
Jev 판단 모델을 활성화하고, 관리자 LLM 라우팅에서 테트리스의 `tetris.play` 워크로드에 연결한다.
회사 전체 생성·판단 기본값을 바꿀 필요는 없다. 판단 모델이 미설정이거나 보안 정책으로
차단되면 게임 진행 중에는 AI 재시도가 계속된다. **AI 플레이 끄기**로 수동 조작할 수 있다.
`OPEN_WORK_HUB_LLM_REQUIRED=true`인 서버의 `/readyz`는 등록된 모든 워크로드의 설정을
요구하므로, 테트리스 AI를 사용하지 않더라도 전체 준비 상태를 통과하려면 이 판단 모델
연결이 필요하다. 생성 모델 기본값만으로 판단 워크로드가 준비되지는 않는다.

- 기본은 수동이다. **AI 플레이 켜기/끄기**로 같은 판의 조작권을 전환한다. 시작 전에도
  AI를 선택할 수 있지만 실제 요청은 게임이 진행 중일 때만 발생한다.
- 게임 엔진이 현재 위치에서 이동·회전 후 도달 가능한 착지와 홀드 후 착지를 계산한다.
  각 후보의 제거할 줄, 덮인 빈칸, 최대·총 높이, 표면 굴곡과 필요한 키 입력 수를 비교한다.
  각 착지 뒤에는 화면에 보이는 다음 블록을 놓는 경우와 보관 블록으로 교환하는 경우를
  각각 탐색해 대표 결과를 하나씩 붙인다. 두 번째 배치 결과와 남는 홀드까지 비교하므로
  지금 줄을 제거하는 후보와 다음 블록을 위한 자리를 남기는 후보를 함께 평가한다.
  즉시 결과와 후속 결과 모두에서 열등한 후보를 줄이고, 현재·다음 배치와 홀드 사용 여부를
  섞어 최대 32개를 Jev에 제공한다. 대표 후속 결과는 빈칸·높이·줄 제거·굴곡·총 높이·입력 수
  순으로 선정한 관측값이며 이후 실행할 경로를 확정하는 것은 아니다.
  빈 홀드에 현재 블록을 넣으면 유일하게 보이던 다음 블록을 바로 사용하므로 그 후보의
  후속 예측은 **알 수 없음**으로 표시한다. 숨겨진 기물 순서는 사용하지 않는다.
  Jev가 착지를 선택하면 경로의 **첫 버튼 하나만** 실행하고 다시 판단한다.
  보드 배열만 보고 모델이 충돌·회전·착지 규칙을 추론하게 하지는 않는다.
  후보 탐색은 별도 Web Worker에서 실행해 UI와 낙하 타이머를 막지 않는다. 요청 완료·오류·
  취소 시 worker를 정리한다. 판단 중에도 레벨별 중력은 계속 작동한다. AI가 켜져 있으면 수동 이동 버튼과 키는
  비활성화되고 일시정지·재개·다시 시작·AI 끄기는 가능하다.
- 요청은 한 번에 하나, 시작 간격 최소 250ms다. 화면에 보이는 다음 기물 하나와
  보드·현재 기물·홀드·게임 지표 및 계산한 후보를 API에 전송한다. 모델에는 후보의 결과
  지표와 두 번째 배치 예측, 후보별 홀드 사용·보관 결과, 현재·다음·홀드 기물 종류,
  홀드 가능 여부와 레벨을 제공한다. 기물이 바뀌거나 조작권·회차가 바뀌면
  이전 판단은 적용하지 않는다. 같은 기물이 아래로 이동한 경우 현재 위치에서 실행한다.
- 판단 API의 제한 시간은 30초, 브라우저의 제한 시간은 35초다. AI 판단이 실패하면
  **게임이 끝날 때까지 횟수 제한 없이 1초 간격으로 재시도**한다. 서버 응답 오류,
  네트워크 연결 실패, 클라이언트 시간 초과와 로컬 계산 오류 모두 같은 규칙을 적용한다.
  화면에 **AI 재시도 중 (횟수회)**를 표시하고 낙하는 계속한다.
  이전 요청이 끝난 뒤 최신 보드·기물을 새로 관측해 판단하며, 성공하면 연속 실패 횟수를
  초기화한다. 공통 판단 어댑터의 호출 내부 재시도는 없고 각 새 판단은 별도로 감사된다.
  재시도마다 서버 인증·앱 접근 권한과 입력 검증을 그대로 적용하며 오류 때문에 자동으로
  AI를 끄지는 않는다. 게임 종료 시 재시도 대기를 취소하고 진행 중인 브라우저 요청도 취소한다.
  AI 끄기·일시정지·다시 시작·앱에서 나가기도 대기 중인 재시도를 취소한다.
- 게임 종료·명시적인 일시정지·AI 끄기·앱에서 나가기는 새 요청을 멈춘다. 이미 시작한 서버 호출은
  끝나며 감사/사용량에 남을 수 있지만 무효화된 응답은 게임에 적용하지 않는다.
- `POST /api/v1/tetris/decision`은 로그인과 현재 앱 접근 권한을 확인하고
  `execute_decision`을 사용한다. 모델·연결·비밀값은 앱에서 선택하지 않는다.
  판단 지연이 길거나 레벨이 높으면 조작할 시간이 줄어든다. 게임 성적은 보장하지 않는다.
  후보 계산은 현재 높이에서 이동·회전 후 즉시 낙하하는 범위이며 아래로 내려간 뒤
  틈에 끼워 넣는 경로와 두 번의 배치를 넘는 장기 계획은 계산하지 않는다. 후보 계산 자체는
  게임을 조작하지 않으며 모델 오류를 대신하는 자동 플레이도 없다.

## 확인과 복구

기본 검증은 엔진(이동·충돌·회전·줄 제거·점수·레벨·보관·종료), UI 키보드/화면 조작과
일시정지·재시작, 서버 앱 허용/해제, 앱 목록 진입·재접속·좁은 화면을 포함한다.

```bash
pnpm generate:app-contracts
pnpm check:app-contracts
pnpm exec vitest run --config apps/web/vite.config.mts apps/web/src/app-modules/tetris
pnpm nx typecheck web
uv run --frozen --directory apps/api --group dev pytest tests/test_tetris_app.py tests/test_tetris_decision.py -q
pnpm exec playwright test --config apps/web/playwright.config.ts apps/web/e2e/tetris.spec.ts
```

API 검사는 저장소 테스트 환경의 비운영 PostgreSQL을 사용한다. Playwright는 실제 Web과
테스트용 bootstrap 응답으로 브라우저 흐름을 검사하므로 설치된 서버에서도 별도로 확인한다.
관리자와 허용된 사용자의 앱 진입, 비허용 사용자의 직접 URL 차단, 게임 시작·이동·회전·
내리기·점수 증가·일시정지·재개를 확인한다. 검증 중 테스트가 사용하는 계정이나 권한을
운영 데이터에 직접 삽입하지 않는다.

AI 검증에는 지연 중 낙하·요청 중복 방지·기물 교체/재시작/모드 전환 후 늦은 응답 무시,
창·탭·게임 포커스 이탈 후에도 계속되는 낙하와 AI 조작,
일회성 오류 후 최신 보드로 재시도·조작 복구, 연속 실패 중 1초 간격의 무제한 재시도와
계속되는 낙하·게임 종료 시 요청 중단·AI 끄기 후 수동 조작, 좌우 빈칸·회전·홀드의 줄 제거 후보와 충돌·후보 수
제한, 다음 블록을 위한 줄 제거 준비, 홀드 보존/교환, 숨겨진 블록 제외와 worker 취소·오류를
포함한다. 실제 Jev 확인은 최대 30초 또는 60회 요청으로 제한하고 모델·호출 수·
응답 시간·사용량 및 실제 이동·회전·**제거한 줄**을 확인한다. 낙하 점수나 API 성공만으로
플레이 품질이 검증되었다고 판단하지 않는다. 게임 보드나 인증값을 로그로
남기지 않는다. 외부 모델의 실호출 검증과 결정적인 회귀 테스트 결과는 구분한다.

앱이 보이지 않으면 회사의 앱 활성화와 대상 사용자를 확인한다. 조작이 되지 않으면 일시정지
상태와 보드 포커스를 확인한다. 앱을 비활성화하면 이후 bootstrap에서 제외된다. 게임 전용 DB
마이그레이션이나 보관 데이터가 없으므로 앱 비활성화에 따른 게임 데이터 정리도 필요 없다.
