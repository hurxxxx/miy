# 테트리스

개인 앱 `/apps/tetris`에서 실행하는 단독·2인 대결 게임이다. 기존 OWH Web/API와 함께
설치한다. 수동 플레이에는 AI 연결이 필요 없으며, AI는 공통 판단·생성 워크로드를 사용한다.

## 설치와 앱 활성화

[개발 환경 설치](../../../INSTALL.md)를 완료하고 API·Web을 실행한다. 플랫폼 관리자가
**관리자 설정 → 앱 사용/접근 설정 → 테트리스**를 켜고 사용할 사용자 또는 그룹을 선택한다.
새 앱의 기본 상태는 비활성·선택 대상이다. 활성화 후 **개인 앱 → 테트리스**에서 연다.
앱 ID `tetris`, 개인 실행·리소스 범위는 [앱 등록 계약](../../../packages/contracts/app-contracts.json)이
소유한다. 서버 bootstrap과 API가 앱 접근을 확인한다. 운영 반영은
[릴리스 절차](../../domains/release/README.md)를 따른다.

AI를 사용하려면 관리자가 [공통 모델 설정](../../domains/ai/gateway.md#user-model-selection)에서
연결과 호환 모델을 활성화한다. `tetris.play`는 `decision` 기능이 있는 판단 모델,
`tetris.play.generation`은 `chat` 기능과 JSON Schema 응답을 지원하는 생성 모델을 사용한다.
생성 호출은 [공통 직접 호출 어댑터](../../domains/ai/gateway.md#direct-completion-exceptions)의
명시적 예외로 등록되어 Hermes 설치 없이 실행한다. 모델·키·경로는 공통 관리자 설정에서 가져온다.
`OPEN_WORK_HUB_LLM_REQUIRED=true`일 때 `/readyz`는 두 등록 워크로드 모두의 기본 라우팅을
검사하므로 생성·판단 계열을 각각 설정한다. 게임 전용 프로세스·포트·DB 마이그레이션은 없다.

## 플레이와 대결 규칙

- 앱을 열면 양쪽 모두 **AI**로 준비한다. 플레이어 1은 판단 워크로드의 기본 모델,
  플레이어 2는 생성 워크로드의 기본 모델을 카탈로그에서 선택한다. **게임 시작**을 눌러야
  플레이와 요청을 시작한다. 기본 모델이 없으면 임의로 대체하지 않고 호환 모델을 직접
  선택할 때까지 시작을 막는다. 모델 새로고침은 사용자가 선택한 모델을 덮어쓰지 않는다.
- 플레이어 2를 **없음**으로 두면 단독 플레이, **사람** 또는 **AI**로 선택하면 대결이다.
  참가 여부와 관계없이 양쪽 보드와 플레이어 설정은 항상 표시한다. **없음**인 보드는
  진행·조작하지 않으며 단독/대결 전환 시에도 보드의 배치를 유지한다.
  사람은 한 명까지 가능하며 AI 대 AI와 어느 쪽이든 사람 대 AI를 지원한다.
  조작 방식·AI 모델은 진행 중 바꿀 수 있다. 참가자 수는 시작 전이나 종료 후 변경한다.
- 양쪽 보드의 기물 순서는 독립적으로 무작위 생성한다. 한 번에 1/2/3/4줄을 제거하면
  상대에게 각각 0/1/2/3줄을 **즉시** 보낸다. 회색 공격 줄마다 독립적으로 무작위 한 칸이 비어 있다.
  공격 상쇄·대기열·연속 제거 보너스는 없다.
- 공격은 쌓인 보드를 위로 밀고 아래에 추가된다. 떨어지는 기물은 원래 위치를 유지하며,
  겹칠 때만 충돌이 해소되는 최소 높이까지 올린다. 쌓인 블록이 위로 넘치거나 기물을
  둘 공간이 없으면 패배한다. 한쪽이 패배하면 승자를 표시하고 양쪽 게임과 AI를 중단한다.
- **게임 시작/다시 시작**, **일시정지/재개**는 양쪽에 함께 적용한다.
- 유일한 사람 플레이어의 보드에서 방향키 좌우 이동, 아래 빠른 낙하, 위/X 시계 방향 회전,
  Z 반시계 방향 회전, Space 즉시 낙하, C 보관을 사용한다. 보관은 기물을 놓기 전 한 번만 가능하다.
  사람 보드의 화면 버튼도 지원한다. P/Esc는 전체 일시정지·재개다. 다른 입력란의 키는 가로채지 않는다.
- 점수·제거한 줄·레벨·보낸 줄, 다음 기물·보관 기물을 각 보드에 표시한다.
  데스크톱에서는 두 보드를 중앙에 같은 높이로 나란히 배치하고, 좁은 화면에서는 위아래로 표시한다.
  사람/AI 및 모델 선택은 각 플레이어 패널에서 바꾼다. 화면 높이에 맞춰 보드를 조절하며,
  게임에서는 비어 있는 앱 보조 사이드바를 표시하지 않는다.
- 데스크톱의 **화면 조작**을 펼치면 이동·회전 버튼을 사용할 수 있다. 좁은 화면에서는
  터치 버튼을 바로 표시한다. 상세 키보드 안내와 규칙은 하단 **조작법과 대결 규칙**에서 펼친다.
  모델 새로고침은 모델 선택 옆에 있으며, 호출 전에는 **게임 시작 대기/아직 응답 없음**을 표시한다.
- 창·탭·게임 밖으로 포커스가 이동해도 계속 진행한다. 브라우저의 백그라운드 실행 제한으로
  타이머와 요청 간격이 늦어질 수 있다. 다른 앱으로 이동하거나 새로고침하면 게임은 초기화된다.
  게임은 일시적인 화면 상태로 서버 저장·순위표·브라우저 저장소 보관 기능은 없다.

## AI 플레이

`GET /api/v1/tetris/models`는 로그인과 앱 접근을 검사한 뒤, 활성 연결·모델의 기능과
워크로드 경로·공급자 허용 정책을 만족하는 카탈로그만 반환한다. **모델 새로고침**으로
관리자의 변경을 반영한다. Jev 또는 특정 LLM 이름을 코드에 고정하지 않는다. 기본 모델과
선택 가능한 모델은 현재 서버 설정이 결정한다. 양쪽에 서로 다른 모델을 선택할 수 있다.
선택 항목이 삭제·비활성화되어도 다른 모델로 자동 대체하지 않는다.

`POST /api/v1/tetris/decision`은 카탈로그 ID와 종류를 받아 고정된 두 워크로드 중 하나를
호출한다. [공통 게이트웨이](../../domains/ai/gateway.md#user-model-selection)가 선택 권한,
모델 기능·연결·경로를 매번 재검증한다. 판단 모델은 `execute_decision`, 생성 모델은
`execute_llm`을 사용한다. 생성 요청은 에이전트 반복 없이 한 번의 모델 호출로 처리한다.
생성 응답은 선택지 enum만 허용하는
`{"choice": "option_N"}` JSON Schema로 검증하며, 원문 텍스트를 임의로 파싱해 실행하지 않는다.
인증·앱 접근·보안 검사·사용량 감사는 기존 공통 실행 경로가 소유한다.

생성 워크로드는 [공통 추론 끔 정책](../../domains/ai/gateway.md#non-reasoning-workloads)을
선언한다. 기본 모델과 사용자가 선택한 모델 모두 `reasoning_effort=none`으로 호출하며,
관리자가 `non_reasoning` 기능을 승인한 모델만 목록과 실행에서 허용한다. 추론 필수 모델이나
지원 여부가 확인되지 않은 모델은 선택할 수 없다. 모델 이름에 따른 예외나 추론 재활성화는 없다.
구조화 결과의 출력 예산은 1024토큰이며 관리자 설정의 상한을 초과하지 않는다.
공통 LLM 실행 오류와 시간 초과도 동일한 판단 실패 응답으로 처리한다.
모델 출력이 예산을 초과하면 결과 JSON을 완성하기 전에 상한에 도달할 수 있다.
이 경우 감사 기록에 `output token limit reached`가 남고 불완전한 결과는 실행하지 않는다.
직접 호출은 에이전트 반복 비용을 제거하지만 모델의 추론 지연이나 게임 조작 품질을 보장하지 않는다.

엔진은 현재 위치에서 이동·회전 후 도달 가능한 착지와 홀드 후 착지를 계산한다. 각 후보는
제거할 줄·공격 줄, 덮인 빈칸, 최대·총 높이, 표면 굴곡, 필요한 입력 수, 보관 결과를 설명한다.
화면에 보이는 다음 기물 배치와 홀드 교환을 각각 탐색해 두 번째 배치의 대표 결과도 붙인다.
후속 결과는 빈칸·높이·줄 제거·굴곡·총 높이·입력 수 순으로 선정한 관측값이다. 즉시 결과와
후속 결과에서 열등한 후보를 줄여 최대 32개를 제공한다. 빈 홀드 사용으로 유일하게 보이는
다음 기물을 소비하면 그 다음은 **알 수 없음**으로 처리한다. 숨겨진 기물 순서는 전달하지 않는다.

두 종류 모델 모두 같은 후보·현재/다음/보관 기물·홀드 가능 여부·레벨을 받으며, 대결에서는
상대의 공개 보드·현재/다음/보관 기물·점수·줄·레벨과 공격 규칙도 받는다. 모델이 착지를
고르면 경로의 **첫 버튼 하나만** 실행하고 다시 관측한다. 후보 계산은 Web Worker에서
실행하며 완료·오류·취소 시 정리한다. 후보 계산과 요청 중에도 양쪽 중력은 독립적으로 작동한다.

판단 모델과 생성 모델은 같은 게임 규칙과 전략 지침을 받는다. 대결의 목표는 상대가 먼저
쌓여 패배하도록 하는 것이며 점수로 승자를 정하지 않는다. 안전하게 가능한 **4줄 동시 제거**를
작은 제거보다 우선하고, 현재·다음·보관 기물과 두 번째 배치 예측을 이용해 4줄 기회를 준비한다.
열린 한 열을 유지하고 I 기물을 보관·활용할 수 있지만 보이지 않는 I 기물의 도착을 가정하지 않는다.
한 번의 4줄 제거는 3줄 공격, 두 번의 2줄 제거는 합계 2줄 공격임을 명시하고 후보에도 두 배치의
총 공격 줄 수를 계산해 전달한다. 당장 패배 위험이 크면 작은 제거로 살아남고, 작은 공격으로
상대를 끝낼 수 있으면 즉시 공격한다. 이 지침은 모델의 선택 기준이며 엔진의 규칙이나 후보 선택을
강제로 바꾸지 않는다. 생성 모델의 추론 끔 정책과 비동기 조작은 유지한다.

플레이어마다 진행 중인 요청은 하나이며 정상 요청 시작 간격은 최소 250ms다. 한쪽의 응답을
다른 쪽이 기다리지 않는다. 기물 교체, 공격으로 인한 보드 변경, 조작 방식·모델 변경,
일시정지·재시작 뒤의 오래된 판단은 적용하지 않는다. 같은 기물의 자연 낙하만 있었다면
현재 위치에서 해당 버튼을 실행한다. 모델 변경 시 기존 요청이 끝난 뒤 새 모델로 요청한다.

판단 API 제한 시간은 30초, 브라우저 제한 시간은 35초다. 모델 응답·연결·시간 초과·로컬
계산 오류가 발생하면 실패한 요청이 끝난 뒤 **500ms 후 최신 상태로 무제한 재시도**한다.
화면에 연속 실패 횟수를 표시하며 성공하면 초기화한다. 게임 종료·일시정지·AI 끄기·재시작·
앱 이탈은 기존 재시도 대기를 취소한다. 종료·앱 이탈 시 진행 중인 브라우저 요청도 취소한다.
이미 시작한 서버 호출은 완료되며 감사/사용량에 남을 수 있다. 오류 때문에 AI를 자동으로 끄거나
다른 모델·자동 플레이로 대체하지 않는다.

실패한 요청도 화면에서 구분한다. 성공 전 실패가 있으면 **아직 성공한 응답 없음**과 함께
모델 공급자 호출 제한, 모델 출력 상한 초과 또는 모델 응답 시간 초과를 표시한다.
공급자 원문 오류는 표시하지 않으며 다음 성공 응답이 오면 실패 표시를 지운다.

모델 종류·이름·공급자와 실제 성공 응답 모델, 최근 응답 시간 및 최근 성공 20회의 평균을
표시한다. 화면의 시간은 후보 계산과 네트워크를 포함한 브라우저 관측 시간이다. 모델·조작 방식·
게임 회차를 바꾸면 통계를 초기화한다. API의 `latency_ms`는 서버에서 관측한 실행 시간이다.
좁은 화면에서는 응답 정보를 보드 아래에 표시한다. 시간의 이름과 값을 분리하고 숫자는
줄바꿈하지 않는다. 상태·시간·모델 정보의 표시 공간을 유지해 응답 전후나 자릿수 변화로
다음 플레이어의 위치가 움직이지 않도록 한다.
블록 칸의 문자도 칸 높이를 늘리지 않도록 제한해 낙하 중 보드 크기를 유지한다.
느린 모델은 낙하 전에 조작할 기회가 적다. 후보 탐색은 현재 높이에서 이동·회전 후 즉시
내리는 범위이며, 내려간 뒤 틈에 끼워 넣는 경로나 두 번의 배치를 넘는 장기 계획은 계산하지 않는다.

## 확인과 복구

```bash
pnpm check:app-contracts
pnpm check:api-contract
pnpm exec vitest run --config apps/web/vite.config.mts apps/web/src/app-modules/tetris
pnpm nx typecheck web
uv run --frozen --directory apps/api --group dev pytest tests/test_tetris_app.py tests/test_tetris_decision.py -q
pnpm exec playwright test --config apps/web/playwright.config.ts apps/web/e2e/tetris.spec.ts
```

공통 게이트웨이나 계약을 변경하면 [검증 지침](../../agents/vibe-coding-harness.md)에 따라
API·Web 전체 검증도 수행한다. API 검사는 비운영 PostgreSQL을 사용한다. Playwright는
테스트용 bootstrap·모델 응답을 사용하므로 설치된 서버에서도 별도로 확인한다.

회귀 검사는 공격량·각 줄의 구멍·충돌 시 최소 상승·넘침 패배, 한 명만 사람 허용,
P2 없음 단독 플레이, 각 AI의 독립 요청과 중력, 500ms 재시도·오래된 응답 무시·전체 종료,
모델 카탈로그 변경과 기능/경로/권한 재검증, 구조화 응답 실패, 숨겨진 기물 제외,
화면/키보드 조작·좁은 화면·다국어를 포함한다.

실제 모델 검증은 한 세션 최대 30초 또는 양쪽 합계 60회 요청으로 제한하고 모델·호출 수·
응답 시간·사용량 및 이동·회전·제거한 줄을 확인한다. API 성공이나 낙하 점수만으로 플레이
품질이 검증되었다고 판단하지 않는다. 게임 보드·인증값·원문 프롬프트를 로그로 남기지 않는다.
실호출 결과와 결정적인 회귀 테스트 결과는 구분한다.

앱이 보이지 않으면 회사의 앱 활성화·사용자 대상을 확인한다. 모델이 없으면 활성 연결·기능·
경로·허용 공급자와 워크로드 설정을 확인한다. 오류가 반복되면 모델을 바꾸거나 일시정지하고
공통 감사 기록을 확인한다. 게임 데이터가 저장되지 않으므로 앱 비활성화에 따른 데이터 정리는 없다.
